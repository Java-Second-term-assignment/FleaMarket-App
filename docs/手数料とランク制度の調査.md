# 手数料・ランク制度 実装調査レポート

## 1. 手数料の実装状況

### 1.1 データベース・ドメイン

| 対象 | 内容 |
|------|------|
| **user_ranks** | ランクマスタ。`commission_bps`（0〜10000 = 0%〜100%）を持つ。 |
| **orders** | `applied_commission_bps`（適用した手数料率 bps）、`item_price_amount`、`shipping_fee_amount`、`total_amount` を持つ。 |

- 手数料率は **bps（basis points）** で保持（100 bps = 1%）。
- 注文には「その取引で適用した手数料率」を `applied_commission_bps` として保存する設計。

### 1.2 注文作成時の実装（OrderService）

**現状:** `createOrderFromProduct` 内で以下が固定されている。

- `applied_commission_bps` → **常に 0**
- `shippingFee` → **常に 0**
- `total` = 商品価格 + 配送料（実質 商品価格のみ）

**結果:** 出品者のランク（user_ranks.commission_bps）を参照しておらず、手数料は一切計算・記録されていない。

```java
// OrderService.java 抜粋
e.setAppliedCommissionBps(0);   // ← 常に0。出品者ランク未使用
long total = price + shippingFee; // 手数料は total に含まれていない
```

### 1.3 注文確認画面（/order/confirm）

- 表示用の `order` は `OrderPageController#orderConfirm` で Map として組み立て。
- **手数料用のキーは存在しない。**
- テンプレート `order_confirm.html` では「手数料」行が **固定で「¥ 0」** 表示。

→ ランクに基づく手数料の計算・表示は未実装。

### 1.4 出品画面（product_add）の「販売手数料」

- テンプレートで `${fee}` を表示（`fee != null ? '¥' + fee : '-'`）。
- **ListingPageController** では `fee` を model に追加していない。
- そのため **常に `fee` は null** となり、画面上は「-」と表示される。出品者ランクに基づく手数料の計算・表示は未実装。

## 2. ランク制度の実装状況

### 2.1 DB シード（V2__seed.sql）の実際の値

| id | rank_code | rank_name | commission_bps | 割合 |
|----|-----------|------------|----------------|------|
| 1 | BRONZE | ブロンズ | 1000 | 10% |
| 2 | SILVER | シルバー | 800 | **8%** |
| 3 | GOLD | ゴールド | 600 | **6%** |

- **プラチナ** は DB に存在しない。

### 2.2 利用規約（terms.html）の記載

**第7条（販売手数料およびランク）:**

- プラチナ：**3%**
- ゴールド：**5%**
- シルバー：**7%**
- ブロンズ：**10%**

**ランク条件（要約）:**

- プラチナ：過去3ヶ月連続で10回以上かつ月額50,000円の取引
- ゴールド：3ヶ月連続で5回以上かつ月額10,000円の取引
- シルバー：2ヶ月連続で3回以上かつ月額5,000円の取引
- ブロンズ：シルバー基準を満たさない場合

### 2.3 ランクの運用

- 新規ユーザーは `RegistrationService` で **INITIAL_RANK_ID = 1（ブロンズ）** で登録。
- `UserRankService` でランク取得、`UserMeResponse` で `commissionBps` を API 返却。
- **ランクの昇格・降格ロジック**（取引実績に応じてランクを更新する処理）は **未実装**。  
  - `ReviewService` のコメントに「レビュー両者揃いで user_ranks 反映」とあるが、実装はされていない。

## 3. 整合性の問題まとめ

### 3.1 規約と DB の不整合

| ランク | 規約の手数料 | DB (commission_bps) | 整合 |
|--------|--------------|---------------------|------|
| プラチナ | 3% | **存在しない** | ❌ |
| ゴールド | 5% | 6% (600 bps) | ❌ |
| シルバー | 7% | 8% (800 bps) | ❌ |
| ブロンズ | 10% | 10% (1000 bps) | ✅ |

- 規約では「プラチナ〜ブロンズ」の4段階だが、DB にはブロンズ・シルバー・ゴールドの3段階のみ。
- ゴールド・シルバーは規約より **1% 高く** 設定されている。

### 3.2 手数料が注文に反映されていない

- 注文作成時に **出品者のランク（commission_bps）を参照していない**。
- `applied_commission_bps` は常に 0。
- 請求金額（total）に手数料が含まれていない。
- 出品画面・注文確認画面のいずれでも、ランクに基づく手数料の計算・表示がされていない。

### 3.3 ランク制度の運用不足

- ランクの昇格・降格（取引実績やレビューに基づく更新）の処理が存在しない。
- 規約に書かれた「ランク条件」を満たしても、システム側でランクが変わらない。

---

## 4. 推奨対応（優先度順）

1. **規約と DB の一致**
   - 利用規約の手数料率に合わせて `user_ranks.commission_bps` を修正するか、
   - 規約の文言を DB の現状（ブロンズ10%/シルバー8%/ゴールド6%、プラチナなし）に合わせて修正する。
   - プラチナを運用する場合は、ランクマスタにプラチナ（例: 300 bps = 3%）を追加する。

2. **注文に手数料を反映**
   - 注文作成時（`OrderService.createOrderFromProduct`）に、**出品者（seller）の user_rank_id からランクを取得**し、その `commission_bps` を `applied_commission_bps` にセットする。
   - 手数料額 = 商品価格 × (applied_commission_bps / 10000)。  
     必要に応じて `total_amount` = 商品価格 + 配送料 + 手数料 のようにするか、手数料は「売上から控除」として別管理とするか、仕様を決める。

3. **画面での手数料表示**
   - **出品画面:** 出品者（ログインユーザー）のランクと商品価格から手数料額を算出し、`fee` として model に渡し、「販売手数料」を表示する。
   - **注文確認画面:** 出品者ランクに基づく手数料を計算し、`order` に「手数料」「合計」を含めて表示する（現状の固定「¥ 0」をやめる）。

4. **ランク昇格・降格（中長期）**
   - 規約の「ランク条件」に合わせ、取引実績（回数・金額・期間）を集計し、`user_ranks` を更新するバッチまたはイベント処理を検討する。
   - レビュー完了時のランク反映は `ReviewService` のコメントどおり、ここで実装するか別サービスに分離するかを決める。
