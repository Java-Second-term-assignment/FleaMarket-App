# 実装されていない機能の詳細調査（REST除く）

バックエンド・フロントエンド（Thymeleaf/JS）の観点で、実装が未完了または不整合な機能をまとめた調査です。REST API関連は除外しています。

---

## 1. カート機能（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `product_detail.html` 79行目: `<form th:action="@{/cart/add}" method="post">`。`cart.html` で `/cart/remove`, `/cart/checkout` |
| **バックエンド** | `CartPageController`, `CartService` で `/cart/add`, `/cart`, `/cart/remove`, `/cart/checkout` を実装済み |
| **補足** | セッション保存、商品ごとに個別注文を作成するチェックアウト |

---

## 2. 商品ページのレビュー投稿（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `product_detail.html` 139行目: `th:action="@{/product/{id}/review(id=${product.id})}"`。ログイン時のみフォーム表示 |
| **バックエンド** | `ProductPageController.productReviewPost()` で `POST /product/{id}/review` を実装。COMPLETED 注文の買い手または売り手がレビュー投稿可能。`ReviewService.submitReview(order.getId(), ...)` で注文単位のレビューとして保存 |
| **挙動** | ログイン済みで当該商品の取引を完了している場合、レビュー投稿後に商品詳細へリダイレクトし成功メッセージ表示 |
| **補足** | 同一商品に複数 COMPLETED 注文がある場合、`findByItemIdAndStatus` は1件のみ返すため、その1注文に対してのみレビュー可能（複数取引分を個別に評価する仕様ではない） |

---

## 3. パスワード再設定（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `password_reset_request.html`: メールアドレス入力 → `POST /password-reset-request`。`password_reset_form.html`: トークン付きで `POST /password/reset`（password, confirmPassword） |
| **バックエンド** | `AuthPageController`: `/password/forgot`（GET）, `/password-reset-request`（POST）, `/password/reset`（GET・POST）。`PasswordResetService.requestReset(email)` でトークン発行・DB保存・`EmailNotificationSender.sendPasswordResetLink()` でメール送信。`passwordResetService.resetPassword(token, password)` でトークン検証・パスワード更新 |
| **挙動** | メール未登録でも同じ成功メッセージを返す（情報漏洩防止）。メール内リンク `/password/reset?token=xxx` から新パスワード設定可能 |
| **補足** | メール送信は `EmailNotificationSenderImpl`（JavaMailSender）。`app.base-url` とメール設定が必要 |

---

## 4. パスワード変更（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `password_change.html`: `password`, `confirmPassword` を送信 → `POST /password-change`。`user_settings.html` から「パスワードを変更する」で `/password/change` へリンク |
| **バックエンド** | `AuthPageController.passwordChange()` が `password`, `confirmPassword` を受取り、一致チェック・`PasswordChangeService.changePassword(userId, password)` で DB 更新（PasswordPolicy 検証あり） |
| **挙動** | 認証必須。成功時は `/user/settings` へリダイレクトし「パスワードを変更しました。」を表示 |

---

## 5. 通報機能（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `product_detail.html`: 通報ボタンでモーダル表示。ログイン時は `POST /products/{id}/report`（reportType, description） |
| **バックエンド** | `ProductPageController.reportProduct()`, `ReportService.submitReport()`。`ReportEntity`・`ReportRepository` でDB保存 |
| **挙動** | 通報理由（偽物・嫌がらせ・スパム・不適切・その他）と任意の詳細を送信すると通報登録され、商品詳細にリダイレクトして成功メッセージ表示 |
| **補足** | 認証必須。通報一覧・管理者側対応は管理画面（違反リスト・通報商品タブ）で利用可能 |

---

## 6. 商品レビュー表示（対応済み）

| 項目 | 内容 |
|------|------|
| **フロント** | `product_detail.html`: `reviewSummary`, `reviews` を表示 |
| **バックエンド** | `ProductPageController` が `ProductReviewQueryService.getReviewSummary(itemId)` と `getReviewsForItem(itemId)` で実データを渡す。同一商品に紐づく全 COMPLETED 注文のレビューを集計・一覧表示 |
| **挙動** | 商品ごとのレビュー件数・平均・スター表示およびレビュー一覧が表示される |
| **補足** | `OrderRepository.findByItemIdAndStatusOrderByCreatedAtDesc` で複数注文を取得し、各注文のレビューをまとめて集計している |

## 7. 実装済み・連携済み（参考）

| 機能 | 備考 |
|------|------|
| 配送先更新 | `UserPageController` の `POST /user/address/update` と `user_settings.html` のフォームが連携済み |
| 管理者：権限付与・剥奪、有効/無効トグル | `admin/users.html` にフォームあり。`AdminPageController` の `/admin/users/toggle`, `/admin/users/admin-role` 等と連携 |
| 管理者：商品・ユーザー編集、停止・強制削除・ブラックリスト | `admin/products.html`, `admin.js` のモーダル・フォームと `AdminPageController` の各 POST が連携済み |
| 違反リスト・通報商品タブ | `AdminDashboardQueryService.getViolationProducts()` 等とテンプレートで連携済み |
| 注文フロー | `/order/confirm`, `/address`, `/payment`, `/user/orders`, `/user/orders/{id}/confirm|shipment|receipt|cancel|review` が OrderPageController で実装。`order_confirm.html`, `cart.html`, `detail.html` と連携 |
| 掲示板 | `BoardPageController`: `/board`, `/board/{boardId}`, `POST /board/{boardId}/posts`。`board_list.html`, `board_detail.html` と連携 |
| 利用規約 | `AuthPageController`: `GET /terms` → `auth/terms.html` |

## 8. 未実装・不整合の有無（ページ・フォーム送信）

以前「未実装」「スタブ」とされていた以下の機能は、いずれも実装済みです。

| 機能 | 現状 |
|------|------|
| 商品ページのレビュー投稿 | 対応済み（POST /product/{id}/review 実装済み） |
| パスワード再設定 | 対応済み（トークン・メール・/ password/reset 処理あり） |
| パスワード変更 | 対応済み（password/confirmPassword 受取・DB 更新あり） |
| 商品レビュー表示 | 対応済み（複数注文のレビュー集計済み） |

ページコントローラと Thymeleaf フォームの対応関係では、未実装のエンドポイントやスタブのままの POST は検出されていません。

## 9. その他の不整合・スタブ（ユーザー設定・一覧等）

以下は、画面はあるがデータがスタブ・空のまま、または保存が紐づいていない箇所です。

### 9.1 ユーザー設定画面（`user_settings.html`）

| 項目 | 内容 |
|------|------|
| **出品した商品（userProducts）** | **対応済み**。`UserProductsQueryService.listBySeller(userId)` が `ItemRepository.findBySellerIdAndStatusNotOrderByUpdatedAtDesc` で DELETED 以外の自分の出品商品を取得し、サムネイルURL とともに `UserProductItemDto` で渡す。 |
| **通知（notifications）** | **対応済み**。`notifications` テーブルと `NotificationEntity`・`NotificationRepository`・`NotificationService` を追加。取引成立時（`recordOrderPaid` / `createOrderFromProduct`）に売り手へ通知を1件作成。設定画面では `notificationService.listByUser(userId, 50)` で一覧表示。 |
| **通知設定チェックボックス** | **対応済み**。`users.notification_enabled` を追加し、`POST /user/settings/notification` で `notificationEnabled` を保存。`userSettings` は `me.getNotificationEnabled()` で実データを表示。 |
| **クレジットカード表示** | 表示はスタブのまま。登録・削除の保存フローは別途（Stripe 等）実装想定。 |
| **「全体の設定を保存」ボタン** | **対応済み**。通知設定用フォームの `type="submit"` として `POST /user/settings/notification` に送信し、通知設定を保存する。 |

**補足**: お気に入り・配送先更新・パスワード変更は実装済み。プロフィール編集は REST（PATCH /user/me）経由で連携済み。

### 9.2 商品一覧（`product_list.html`）

| 項目 | 内容 |
|------|------|
| **検索・絞り込み** | フォームは `keyword`, `sort`, `category` を GET で送信。`ProductPageController` の `GET /`, `/products` がこれらを受け取り `ProductListService.getProducts()` に渡しており、連携は取れている。 |
| **スクリプト** | 商品一覧テンプレートで `product_confirm.js` を読み込んでいる。この JS は出品確認用（sessionStorage `productConfirm`）のため、一覧表示時は何もせず return するだけ。機能的には問題ないが、テンプレートとスクリプトの対応が紛らわしい。 |

### 9.3 注文・住所

| 項目 | 内容 |
|------|------|
| **注文確認・住所** | `OrderPageController` が `order`, `payment`, `address` をセッションまたは `userService.getDefaultShippingAddress(userId)` から組み立てて渡している。`order_confirm.html` の `order.items`, `address.name/postcode/fullAddress`, `payment.method/installment` と一致。 |
| **住所フォーム** | 注文フロー用 `/address` は `name`, `postcode`, `fullAddress` で送受信。ユーザー設定の配送先は `recipientName`, `postalCode`, `address`, `phone`（`UserAddressDto`）で別定義。意図的な使い分け。 |

### 9.4 管理画面・掲示板

| 項目 | 内容 |
|------|------|
| **管理画面** | `admin/products.html`, `admin/users.html` の編集・凍結・強制削除等のフォームは、`AdminPageController` の各 POST と `admin.js` のモーダル（data-id, data-name 等）と整合。 |
| **掲示板** | `board_detail.html` の投稿フォームは `name="content"` で `POST /board/{boardId}/posts`。`BoardPageController` が `@RequestParam String content` で受け取り連携済み。 |
